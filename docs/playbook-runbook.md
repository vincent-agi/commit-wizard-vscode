# Playbook / Runbook

## Prerequisites

- Node.js 18+ and npm.
- VS Code 1.85+ (matches `engines.vscode` in `package.json`).

## Setup

```bash
npm install
```

## Local development (F5)

1. Open the project root in VS Code.
2. Run `npm run watch` in a terminal (esbuild watch mode; keep it running), or just press `F5` —
   the default `Run Extension` launch config runs `npm: watch` as its `preLaunchTask`.
3. Press `F5` (or **Run > Start Debugging**). A new **Extension Development Host** window opens
   with the extension loaded.
4. Open a Git repository in that host window, click the Activity Bar icon to open **Commit
   Builder**, and exercise the form.
5. Edit a **webview** source file (`src/webview/*`, `src/issueForm/*`) and save: esbuild rebuilds
   `dist/webview.js` / `dist/issueForm.js` and the open Commit Builder and issue form reload
   themselves within a second, keeping what you typed (form state is stored with the webview
   API). This watcher only exists when the extension runs in Development mode (F5); production
   builds never create it.
6. Edit **extension-host** code (everything else) and save: reload the Extension Development Host
   window (`Cmd+R` / `Ctrl+R` inside it, or **Developer: Reload Window**) to pick up the change.

`.vscode/launch.json` and `.vscode/tasks.json` provide this out of the box (see below).

## Running tests

```bash
npm test            # Vitest, single run — core/* unit tests
npm run test:watch  # Vitest watch mode
```

Unit tests cover `src/core/*` only — no VS Code runtime required, so they run in plain Node and
are fast enough for a pre-commit loop.

Integration/E2E tests that need the real Extension Host use `@vscode/test-electron`
(`src/test/runTest.ts`, not wired into `npm test` to keep the default loop fast). Run them with:

```bash
npm run test:e2e   # compiles, downloads/launches a real VS Code, runs src/test/suite/*.test.ts
```

This downloads a full VS Code build on first run and spawns its Electron binary directly — it
needs a normal desktop session and will not run inside a locked-down sandbox/CI container
without Electron/GUI support (spawn fails with `ENOENT`/`code -2` there). Run it on a local
machine or a CI runner with `xvfb`/headless display support.

## Linting & formatting

```bash
npm run lint     # ESLint over src/**/*.ts
npm run format   # Prettier --write
```

## Git hooks in this repository

This repository uses its own **Install Git Hooks** feature (husky). `npm install` runs the
`prepare` script, which activates them. They run:

- `pre-commit`: `npm run lint` and `npm run format:check` (fix formatting with `npm run format`);
- `commit-msg`: commitlint with `commitlint.config.cjs` (Conventional Commits, optional leading
  Gitmoji, e.g. `✨ feat(core): …`);
- `pre-push`: `npm test`.

Skip them once with `HUSKY=0 git commit …`. The hook files are regenerated by re-running the
command; do not hand-edit them without keeping the diff small.

### Trying the installer itself

The extension ships an **Install Git Hooks** command (`gitmojiCommit.installHooks`, see
`docs/user-guide.md`). To try it while developing, press `F5`, open a throwaway Git repository in
the Extension Development Host, and run **Commit Wizard: Install Git Hooks** from the Command
Palette. Verify:

1. the chosen files appear (`.husky/*` or `lefthook.yml`, plus `commitlint.config.cjs`);
2. running the command twice shows no prompt the second time (identical content), and shows the
   **Show diff / Overwrite** modal after you edit a generated file;
3. after running the prefilled install command, `git commit -m "bad message"` is rejected and
   `git commit -m "✨ feat: ok"` passes.

The generated shell checks are exercised for real by `src/core/hookPresets.spec.ts`, which runs
them against temporary Git repositories.

To remove hooks from a test repo: delete the generated files and run
`git config --unset core.hooksPath`.

## Continuous integration

`.github/workflows/ci.yml` runs on every pull request and on pushes to `main`:

| Job | What it does | Required? |
| --- | --- | --- |
| `verify` | `npm ci`, lint, format check, unit tests, compile | yes |
| `commits` | commitlint over the PR's commits (same config as the local `commit-msg` hook) | yes |
| `e2e` | extension-host tests under `xvfb` | no (report only, slow) |

Mark `verify` and `commits` as required status checks in **Settings > Branches** (branch
protection rule for `main`). The workflow has read-only permissions.

## Building

```bash
npm run compile  # tsc typecheck + esbuild bundle -> dist/extension.js
```

## Packaging

```bash
npx vsce package
```

Produces `commit-wizard-vscode-<version>.vsix` in the project root. Sanity-check the
package contents first if `.vscodeignore` changes:

```bash
npx vsce ls
```

Install the packaged `.vsix` locally to verify: Extensions view -> `...` -> **Install from
VSIX...**.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Sidebar icon missing | Extension not activated / `dist/extension.js` missing | Run `npm run compile`, reload window |
| Webview shows blank panel | CSP nonce mismatch or JS error in `clientScript.ts` | Open **Developer: Toggle Developer Tools** in the Extension Development Host, check the Console tab scoped to the webview |
| "No Git repository found" warning on Fill Commit | No folder open, or `vscode.git` extension disabled | Open a folder containing a Git repo; check Extensions view that "Git" (`vscode.git`) is enabled |
| "+" add-scope does nothing | No workspace folder open | Open a folder — `ConfigurationTarget.Workspace` writes require one |
| Issue field not auto-filled | Branch name has no ticket-like token | Expected — see `docs/technical-docs.md` matching rules; edit manually |
| `vsce package` fails on missing `README.md`/`LICENSE` | `vsce` requires these by default | Add a `README.md` (and `LICENSE` if publishing) at the project root |
| Vitest can't resolve `vscode` in a `core/*.spec.ts` | A `core/*` module accidentally imports `vscode` | `core/*` must stay VS Code-free by design (ADR 0001) — move the VS Code-dependent code to `webview/` or `git/` |
